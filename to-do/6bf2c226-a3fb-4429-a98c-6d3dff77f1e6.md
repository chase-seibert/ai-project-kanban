# Close a Codex session for desktop continuation

## Problem and inspected evidence

The user needs to release a StageChase-owned Codex session so they can continue the same conversation in the desktop app without losing its history or working folder.

- `Sources/StageChaseUI/DetailViews.swift`, `RunDetail`: “Open in Codex” only opens `codex://threads/<threadID>`. It does not release ownership. “Stop run” is visible only for active statuses. This shared view appears in both task details and the activity panel.
- `Apps/StageChaseMac/CodexRunner.swift`: successful completion clears `activeID` and drains the queue, but leaves the connection alive. `stop(_:)` interrupts and closes the connection only for active runs, sets Cancelled, then drains again. Thus a finished session has no explicit release control.
- `Apps/StageChaseMac/CodexConnection.swift`: one dedicated stdio app-server process serves the runner. `close()` sends termination and immediately discards the process reference; it does not confirm process exit. Previously loaded threads can share this process. Closing it indiscriminately could interrupt another task.
- `Sources/StageChaseCore/Domain.swift`: `AgentRun` retains thread ID, turn ID, working folder, progress, and outcome. Existing Interrupted status can represent a deliberately released unfinished run; Retry preserves its identity. `finishRun` advances stages and must not be invoked by a close action.
- `Sources/StageChaseCore/Repository.swift`: restart converts active/queued runs to Interrupted without replaying them. Preserve that behavior and the current SwiftData storage.
- `Tests/Integration/RunnerSmoke.swift` and `fake-codex.py` cover completion, blocked work, approvals, stop, retry, and worktree isolation. The fixture currently reuses one thread/turn ID and acknowledges interrupt without a completion event, so it needs stronger lifecycle scenarios.

The likely cause is retained StageChase server ownership, inferred from source. Desktop lock behavior has not been reproduced during this planning turn. Existing deep-link compatibility and successful continuation must be verified on the installed desktop app before claiming the feature works.

Protocol reference: [official OpenAI app-server documentation](https://learn.chatgpt.com/docs/app-server), inspected September 29, 2026. `turn/interrupt` requests cancellation; completion is reported separately. `thread/unsubscribe` removes a subscription but can leave the thread loaded for a 30-minute inactivity grace period. Therefore unsubscribe alone is not proof of immediate release. Do not archive or delete the conversation as a workaround.

## Scope and intended behavior

Add a Mac-only **Close Codex session** button beside the existing session controls, with help text: “Release this session from StageChase so you can continue in the Codex desktop app. Files and conversation history are kept.” Keep **Open in Codex**, **Copy session ID**, and **Reveal working folder** available after release. Closing does not automatically send a prompt or launch another turn.

| Situation | Expected result |
| --- | --- |
| Selected session is running or awaiting approval | Interrupt its turn, release the owned server, save Interrupted with an explanatory activity entry; leave task stage and completion unchanged. |
| Selected session has finished | Release the server; preserve Succeeded, saved plan, stage, result summary, and progress. |
| Failed, stopped, or previously released session | If already disconnected, report that it is released without reconnecting; preserve prior outcome and errors. |
| No saved thread ID | Do not offer session close; retain Stop run for queued/starting work. |
| Another task is active on the shared process | Disable close with a clear explanation that the other run must finish or be stopped first. Never silently stop that task. |
| Close is in progress | Show “Closing…” and disable duplicate close, conflicting retry, and opening this session until release succeeds. |
| Shutdown or persistence fails | Show a recoverable error; do not claim successful handoff or automatically open/resume anything. |

Closing pauses automatic queue draining for this handoff. Already queued tasks stay queued; a later explicit confirmed stage action or Retry may resume queue processing, consistent with the existing failure-pause convention. Reopening views, checking the connection, or polling must not resume work.

Out of scope: new workflow stages, automatic task completion, desktop-to-StageChase result synchronization, iPhone remote control, private Codex database edits, worktree cleanup, dependency installation, commits, publication, or deployment. Desktop continuation remains a manual action in the same saved session and working folder.

## Risks and mitigations

- **Cross-task interruption:** a single process owns multiple loaded threads. Enforce the other-active-run guard in the runner as well as the UI; disable close while a different start is being prepared. Per-run servers are outside this initial scope.
- **Late events and actor reentrancy:** completion, approval, and startup can cross awaits. Use run/turn/connection identity checks and serialized lifecycle transitions; test both completion-before-close and close-before-completion orderings.
- **Premature success:** `Process.terminate()` and interrupt acknowledgment alone do not prove the session is free. Wait for owned-process exit before reporting release. Keep the UI responsive during timeout handling.
- **Partial work:** interruption can leave valid partial edits or a partly written plan. Preserve all files and the exact worktree; tell the user to inspect the session before explicit Retry. Never rewind files or erase history.
- **Persistence failure:** process release and a database transaction cannot be one atomic operation. Pause the queue, surface the error, and ensure a subsequent close/restart recovers without replaying work or marking completion.
- **Desktop compatibility:** the installed app may use a different URL handler, account, or session home. Verify the same thread visibly; use the existing session-ID fallback and report remaining incompatibility instead of copying or rewriting private session storage.
